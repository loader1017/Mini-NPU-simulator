# Mini-NPU-simulator

## 1. 프로젝트 소개

이 시뮬레이터 제작 프로젝트를 통해 맥MAC 연산이 무엇인지 실습해보고, 이를 통해 입력된 패턴이 'Cross(+)'인지 'X'인지 판별하는 시뮬레이터입니다. 외부 라이브러리 사용이 불가함에따라 표준 라이브러리인 json과 time 만 사용했습니다.

## 2. 핵심 구현 사항

MAC 연산 엔진: 2차원 배열을 순회하며 원소별 곱셈과 전체 누적합을 구하는 로직을 구현했습니다.

부동소수점 오차 관리: 연산 결과 비교 시 정밀도 문제를 해결하기 위해 허용 오차(1e-9) 정책을 적용하여 판정의 신뢰도를 높였습니다.

라벨 정규화: +, cross, x 등 다양한 형태의 입력 라벨을 내부 표준(Cross, X)으로 통일하여 비교 로직의 일관성을 유지했습니다.

동점 판정 로직: 두 필터와의 유사도 차이가 오차 범위 내일 경우 UNDECIDED를 반환하여 엄격한 판정을 수행합니다.

## 3. 시간 복잡도 분석 (O(N2))

본 시뮬레이터의 연산 효율성은 입력 데이터의 크기 N에 대해 O(N2) 제곱 의 시간 복잡도를 가집니다.

분석 근거

    중첩 반복문: calculate_mac 함수는 N×N 행렬의 모든 원소를 한 번씩 방문해야 하므로 N×N=N2번의 곱셈 및 덧셈 연산이 발생합니다.

    실측 데이터:
    크기 (N×N)	연산 횟수 (N2)	측정 평균 시간 (ms)
    3 x 3	9	0.005217 ms 
    5 x 5	25	0.010775 ms
    13 x 13	169	0.054992 ms
    25 x 25	625	0.188425 ms
    (실제 측정값은 PC 환경에 따라 다를 수 있으나, 연산 횟수가 커짐에 따라 시간이 비례하여 증가함을 확인했습니다.)		

## 4. 실패 케이스

분석 과정에서 발생한 주요 실패 원인과 해결 방안입니다.

    데이터적 동점: 패턴 내의 모든 값이 동일할 경우 두 필터와의 점수가 같아져 UNDECIDED가 발생합니다. 이는 알고리즘의 문제라기 보단, 데이터를 중심으로 판정하면서 생기는 경우입니다.

    데이터 스키마 오류: data.json의 키와 실제 배열의 크기가 일치하지 않을 경우 ValueError를 발생시키고 예외 처리를 통해 불완전 종료가 나지 않도록 했습니다.

## 5. 실행 방법
```
# 프로그램 실행
python main.py

# 모드 선택
1. 사용자 입력 (3x3 데이터, 필터 직접 입력)
2. data.json 분석 (일괄 검증 및 성능 측정)
0. 종료
```
